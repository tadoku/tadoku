Implementation plan · August 2026

Move admin to TanStack Start—after the design system settles.

A phased, reversible migration of the one-user Tadoku admin application. Preserve URLs and APIs, prove Ory and the container early, add Kubernetes health probes safely, and remove the Next.js environment naming only after production is stable.

Hard prerequisite

Implementation does not begin until the design-system rework is merged, adopted by admin, free of Next.js runtime coupling, and stable for the migration window.

Migration shape

One framework changes. Product behavior does not.

Use TanStack Start plus the file router, retain existing React Query hooks, keep authorization in backend APIs, and use route loaders only for session bootstrap, runtime configuration, redirects, and route UX.

In scope

  • All 18 existing route behaviors and redirects
  • Request-scoped Ory session and admin layout guard
  • Runtime configuration from Kubernetes
  • Start/Nitro production image on port 3000
  • Startup, readiness, and liveness endpoints and probes
  • Final environment-variable cleanup

Deliberately out of scope

  • Admin or design-system redesign
  • Backend, Ory, Keto, or authorization changes
  • React Query upgrade or loader rewrite
  • React Server Components
  • A new E2E environment
  • Migration of other Next.js applications

Risk posture

Prove the boundaries, not every screen.

The route conversion is mechanical. Session cookies, browser-only editors, the production image, and deployment ordering deserve the attention. With one operator and backend-enforced authorization, manual acceptance is proportionate.

Execution

Seven gated phases.

Parallel labels identify work that can be split once the preceding gate establishes shared conventions. Each gate must pass before dependent work begins.

Phase 0

Prerequisite and baseline

Wait for the design-system rework and make rollback concrete.

Confirm design-system completion criteria
Rebase on its merge commit
Inventory routes, Next imports, Ory, config, and Docker
Record current production digest and manual checklist
Gate
Admin builds on the stable design system and a known-good rollback digest is recorded.
Phase 1

Prove the Start runtime

Establish Vite, generated routes, root providers, and one real editor before scaling out.

Create Start/Vite shell and update TypeScript
Create root document and route boundaries
Migrate dashboard and one dynamic editor
Verify CodeMirror and production SSR
Gate
The vertical slice works in development and the production build without UI or backend forks.
Phase 2

Session and runtime foundations

Make security and configuration request-scoped before moving all routes.

[Parallel: config] Server-read env and public root-loader subset
Replace unauthorized redirect route
Gate

Complete the file-route tree

Route families can now migrate independently against one auth/layout convention.

[Parallel] Dashboard and users
[Parallel] Languages

Phase 4

Container and Kubernetes health

Make health observable before Kubernetes begins enforcing it.

[Parallel: app] Add /startupz, /readyz, /livez
[Parallel: image] Build non-root Start/Nitro image
Smoke exact image on port 3000
Deploy and verify endpoints inside the pod
[ArgoCD] Add startup, readiness, and liveness probes
Validate a zero-unavailable rolling update
Gate
All probes pass, the service stays available during rollout, and digest rollback remains viable.
Phase 5

Cutover and manual acceptance

Use the risk model appropriate for one operator; do not build an E2E environment.

Record outgoing and incoming digests
Verify login and return-to
Verify dashboard, deep link, and refresh
Perform one harmless create/edit
Verify logout or session expiry
Revert the ArgoCD digest if any check fails
Gate
The operator accepts the deployment, or production is restored to the recorded digest.
Phase 6

Rename legacy environment variables

Clean up the Next.js naming only after the new runtime is stable.

Add final TADOKU_* names with old-name fallbacks
Update Tilt and production ArgoCD values
Verify production using only final names
Remove fallbacks and all NEXT_PUBLIC_* references
Gate
Both repositories contain no admin NEXT_PUBLIC_* references and login/dashboard still pass.
