01 · Typography proposal

Serif for editorial hierarchy; sans for work

Keep Merriweather and Open Sans, but stop making every heading serif. Large navigational hierarchy gets the bookish voice; components and dense interfaces stay crisp and practical.

Load real weights

Open Sans 700 is currently missing even though `font-bold` is used. UI v2 should ship or document actual 400, 600, and 700 files—never synthetic bold.

Framework-independent fonts

Use optional self-hosted WOFF2 assets and CSS variables. Do not depend on `next/font` or a runtime Google Fonts `@import`.

Respect multilingual text

User-entered Japanese and other scripts stay in the sans/system fallback stack. Serif is reserved for controlled interface headings.

02 · Icon grammar proposal

One family, two intentional modes

Continue with Heroicons initially, but stop choosing solid versus outline ad hoc. Soft stroke endings aid recognition and do not require rounded component containers.

Size roles

Three normal sizes and one illustration exception.

16px
Compact rows and inline metadata
20px
Default buttons, fields, menus, and navigation
24px
Icon-only controls and prominent actions
48px
Empty states only—not ordinary UI

Semantic modes

Outline describes actions; solid confirms state.

03 · Button API recommendation

Classes are the primitive; React is optional

A mandatory Button import would make simple markup less convenient and would couple navigation links to one framework. The class recipe should be the stable cross-framework contract.

Hybrid, with a class-first bias

`ui-v2/styles.css` owns `.btn`, variants, density, focus, disabled, and icon sizing. A Tailwind preset can expose the same tokens. Optional framework adapters add behavior without becoming the only way to obtain the styles.

This means plain HTML, React, another router, or a future non-Next application can all use the same visual contract.

// No component import required
<button className="btn primary">Save</button>
<a className="btn" href="/contests">Contests</a>

// Optional behavior adapter
<Button loading icon={SaveIcon}>Save</Button>

04 · Regression baseline, concretely

Named fixtures plus behavior checks

A baseline is the smallest representative set of UI v2 examples that must continue to render and behave correctly. It does not freeze the old design and it does not initially require screenshots.

ComponentShared style-guide fixturesImmediate automated checks
Buttons and linksPrimary, secondary, danger, disabled, loading, icon-onlyCorrect element, accessible name, disabled behavior, keyboard activation
Form controlsEmpty, filled, error, disabled, help textLabel association, `aria-invalid`, described error, keyboard interaction
OverlaysMenu and modal open/closed statesFocus enters, Escape closes, focus returns to trigger
NavigationDesktop, mobile closed, mobile openLandmarks, toggle name/state, keyboard navigation

How reuse works: the style guide imports a named fixture such as `PrimaryButtonDisabled`; the Vitest/Testing Library suite imports that same fixture and checks its semantics. The later visual-regression issue can screenshot the same fixture without inventing a second catalogue.
